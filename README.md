Пет-проект для изучения многопоточности

Представляет собой сервис для бронирования билетов на различные мероприятия.
Стэк
Java 17, Spring Boot 4.1.0, MVC с REST-эндпоинтами.

Первая проблема - параллельные запросы на бронирование дают успех, но по факту бронируется только то количество, которое доступно. Это race condition.
Эндпоинт /events/{id}/booking
1 решение - synchronized. Блокируется весь метод, нельзя обернуть его в транзакцию
2 решение - пессимистичная блокировка. блокируется только строка 
3 решение - оптимистичная блокировка. блокируется только просмотр колонки с версией.
в проде выбрал бы пессимистичную, потому что при оптимистичной блокировке появляется дополнительная колонка с версией, и её нужно в каждом кастомном Query указывать
